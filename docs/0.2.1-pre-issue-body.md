# v0.2.x SM75 Testing Call

We are opening public testing for the new `v0.2.x` route on dual RTX 2080 Ti / SM75.

This route uses the current migration baseline, vLLM `0.27.1`, and targets CUDA 13.0, PyTorch 2.13, Ubuntu 26+ (Linux kernel 7+), and dual RTX 2080 Ti SM75 systems. It is not a small upgrade of the old `v0.1.x` code: the runtime was migrated again from the official upstream vLLM baseline, then the SM75-specific changes were re-applied and revalidated. The stable `v0.1.x` line was primarily validated around Qwen3.6 27B; the main validation target for this `0.2.x` line is Qwen3.8 27B, including FP8, NVFP4, MTP, CUDA Graph, and multimodal routes.

## What the rebase brings

These changes cannot be obtained by only upgrading CUDA or changing the compiler:

- **V1 scheduling and graph execution:** A common execution contract now covers the unified scheduler, chunked prefill, prefix-cache accounting, speculative decoding, `FULL_AND_PIECEWISE` / piecewise CUDA Graph policies, Model Runner V2, and breakable/dynamic graphs. The shipped `normal` and `fast` profiles depend on this contract; it is not equivalent to changing the toolkit underneath vLLM 0.21.0.
- **Qwen3.x and MTP model contracts:** Upstream Qwen3.5 dense/MoE support, Qwen MTP loading, EAGLE3/speculator integration, GPTQ-MTP fixes, and multimodal ViT CUDA Graph support provide the model and assistant-model interfaces used by the Qwen3.8/Qwen3.x validation routes.
- **Hybrid Mamba/GDN and KV-cache semantics:** Upstream reworked hybrid attention, unified KV-cache layout/specification, fixed Mamba alignment and partial prefix-cache behavior, and connected hybrid models with speculative decoding. These changes cannot be safely filled in with environment variables.
- **TurboQuant and compressed-cache correctness:** Upstream added KV-mode handling and fixed TurboQuant workspace reservation before CUDA Graph capture. Without this class of change, an older route can reserve only a 5 MiB workspace and fail on a later 8 MiB continuation prefill.

Please use the [0.2.x maintenance branch](https://github.com/weicj/vLLM-2080Ti-Definitive/tree/vllm-2080ti-definitive-0.2.x) or the [v0.2.1-pre2 release](https://github.com/weicj/vLLM-2080Ti-Definitive/releases/tag/v0.2.1-pre2). The [detailed testing guide](https://github.com/weicj/vLLM-2080Ti-Definitive/blob/vllm-2080ti-definitive-0.2.x/docs/0.2.1-pre-testing-call.md) contains the shipped profiles, test shape, environment requirements, known limitations, and reporting template.

This is a prerelease, so both successful and unsuccessful results are valuable. Please report startup failures, incorrect output, out-of-memory errors, CUDA Graph capture failures, and unstable graph replay directly; you do not need to find the root cause first.

## Please include

- GPU model, VRAM, NVLink/PCIe topology, driver, CUDA, PyTorch, OS, and GCC.
- Branch or tag and commit, checkpoint URL, profile, mode, KV dtype, and MTP settings.
- Whether the service starts and whether non-eager CUDA Graphs capture and replay successfully.
- Context length, prefill/decode throughput, relevant logs or traceback, and complete output when correctness is affected.

Hardware and checkpoints outside the current table are welcome too. Thank you for helping us validate this migration.
