# v0.2.1-pre SM75 Testing Call

We are opening public testing for `v0.2.1-pre` on dual RTX 2080 Ti / SM75.
This is a prerelease, so both successful runs and failures are useful. If a
route does not start, produces incorrect output, runs out of memory, or loses
CUDA Graph capture, please report it too.

This line is not a small upgrade of the old `v0.1.x` code. It was rebuilt from
the upstream vLLM runtime baseline (`v0.27.1`), and the SM75-specific changes
were then re-applied and revalidated on top of that baseline. The stable
`v0.1.x` line was primarily validated around Qwen3.6 27B; the main validation
target for this `0.2.x` line is Qwen3.8 27B, including FP8, NVFP4, MTP, CUDA
Graph, and multimodal routes.

Please test with the [0.2.x maintenance branch](https://github.com/weicj/vLLM-2080Ti-Definitive/tree/vllm-2080ti-definitive-0.2.x)
or the [v0.2.1-pre release](https://github.com/weicj/vLLM-2080Ti-Definitive/releases/tag/v0.2.1-pre).
The [detailed testing guide](https://github.com/weicj/vLLM-2080Ti-Definitive/blob/vllm-2080ti-definitive-0.2.x/docs/0.2.1-pre-testing-call.md)
contains the supported profiles, test shape, environment notes, and reporting
template.

When replying, please include:

- GPU model, VRAM, NVLink/PCIe topology, driver, CUDA, PyTorch, OS, and GCC.
- Branch/tag and commit, checkpoint URL, profile, mode, KV dtype, and MTP.
- Whether the service starts and produces correct output with non-eager CUDA Graphs.
- Context length, prefill/decode throughput, and the relevant logs or traceback.

Thank you for testing this migration with us. Results from hardware and
checkpoints that are not in the current table are welcome as well.
