# v0.2.x SM75 测试征集

我们现在开始征集双 RTX 2080 Ti / SM75 上的新路线 `v0.2.x` 测试反馈。

本路线采用当前迁移基线 vLLM `0.27.1`，面向 CUDA 13.0、PyTorch 2.13、Ubuntu 26+（Linux kernel 7+）以及双 RTX 2080 Ti 的 SM75 环境。它不是在旧 `v0.1.x` 代码上做的小版本升级，而是从官方上游 vLLM 运行时重新迁移，再重新应用和验证 SM75 专用改动。稳定的 `v0.1.x` 主要围绕 Qwen3.6 27B；这条 `0.2.x` 线路当前主要验证 Qwen3.8 27B，包括 FP8、NVFP4、MTP、CUDA Graph 和多模态路线。

## 这次 rebase 带来的变化

这些内容不是单纯升级 CUDA 或更换编译器能够得到的：

- **V1 调度与图执行**：统一 scheduler、chunked prefill、prefix-cache 计账、speculative decoding、`FULL_AND_PIECEWISE` / piecewise CUDA Graph、Model Runner V2，以及 breakable/dynamic graph 执行契约。当前 shipping 的 `normal` 和 `fast` profile 都依赖这套契约，不等价于在 vLLM 0.21.0 上更换 toolkit。
- **Qwen3.x 与 MTP 模型契约**：Qwen3.5 dense/MoE、Qwen MTP 加载、EAGLE3/speculator、GPTQ-MTP 修复，以及多模态 ViT CUDA Graph 支持。这些是 Qwen3.8/Qwen3.x 验证路线使用的模型和 assistant-model 接口基础。
- **混合 Mamba/GDN 与 KV cache 语义**：hybrid attention 重构、统一 KV-cache layout/specification、Mamba 对齐和 partial prefix-cache 修复，以及 hybrid 模型与 speculative decoding 的协同。这些变化不能靠环境变量安全补齐。
- **TurboQuant 与压缩 cache 正确性**：KV mode 处理，以及 CUDA Graph 捕获前预留 TurboQuant workspace 的修复。缺少这类变化时，旧路线可能只预留 5 MiB workspace，后续 8 MiB continuation prefill 就会失败。

请使用 [0.2.x 维护分支](https://github.com/weicj/vLLM-2080Ti-Definitive/tree/vllm-2080ti-definitive-0.2.x) 或 [v0.2.1-pre2 release](https://github.com/weicj/vLLM-2080Ti-Definitive/releases/tag/v0.2.1-pre2)。[详细测试说明](https://github.com/weicj/vLLM-2080Ti-Definitive/blob/vllm-2080ti-definitive-0.2.x/docs/0.2.1-pre-testing-call.zh-CN.md) 中包含已发布 profile、测试形状、环境要求、已知限制和反馈模板。

这是预发布版本，跑通和跑不通的结果都很有价值。如果启动失败、输出不正确、显存不足，或者 CUDA Graph 没有成功捕获和稳定 replay，也请直接反馈，不需要等到找到完整原因后再发。
