# v0.2.1-pre SM75 测试征集

我们现在开始征集双 RTX 2080 Ti / SM75 上的 `v0.2.1-pre` 测试反馈。这是
预发布版本，所以跑通和跑不通的结果都很有价值。如果启动失败、输出不正确、显存
不足，或者 CUDA Graph 没有成功捕获，也请直接反馈，不需要等到找到完整原因后再发。

这条线路不是在旧 `v0.1.x` 代码上做的小版本升级，而是重新从官方上游 vLLM 运行时
基线（`v0.27.1`）迁移，再把 SM75 专用改动重新应用并验证。稳定的 `v0.1.x` 主要围绕
Qwen3.6 27B 验证；这条 `0.2.x` 线路的主要验证目标是 Qwen3.8 27B，包括 FP8、NVFP4、
MTP、CUDA Graph 和多模态路线。

请使用 [0.2.x 维护分支](https://github.com/weicj/vLLM-2080Ti-Definitive/tree/vllm-2080ti-definitive-0.2.x)
或 [v0.2.1-pre release](https://github.com/weicj/vLLM-2080Ti-Definitive/releases/tag/v0.2.1-pre)。
[详细测试说明](https://github.com/weicj/vLLM-2080Ti-Definitive/blob/vllm-2080ti-definitive-0.2.x/docs/0.2.1-pre-testing-call.zh-CN.md)
中包含已发布 profile、测试形状、环境说明和反馈模板。

回复时请尽量提供：

- GPU 型号、显存、NVLink/PCIe 拓扑、驱动、CUDA、PyTorch、操作系统和 GCC。
- 分支或 tag 与 commit、checkpoint 链接、profile、mode、KV dtype 和 MTP 设置。
- 是否能启动，以及非 eager CUDA Graph 是否成功捕获和稳定运行。
- 上下文长度、prefill/decode 吞吐，以及相关日志或 traceback。

也欢迎测试当前表格之外的硬件和 checkpoint。感谢大家一起帮助我们把这条迁移线路
验证完整。
